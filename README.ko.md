# KorDoc 문서변환기 (KorDoc Transform)

[English](README.md)

Obsidian 데스크톱에서 한국 공공·사무 문서를 Markdown 노트로 변환하고, HWPX를 미리 보고 편집하며, Markdown을 다시 HWPX로 내보냅니다. 변환 엔진이 함께 들어 있어 인터넷 연결 없이 내 컴퓨터에서만 처리합니다.

MIT 라이선스 라이브러리 [kordoc](https://github.com/chrisryugj/kordoc)을 쓰는 비공식 플러그인입니다(엔진 버전 4.24.59, 플러그인 버전 4.24.59r1).

## 기능

- **Markdown 변환:** HWP, HWPX, HWPML, PDF, 엑셀(XLS·XLSX), 워드(DOCX), 파워포인트(PPTX). 그림은 노트 옆에 뽑아 저장하고, 표·각주·제목을 유지합니다. 저장 폴더, 쪽 범위, frontmatter, 레이아웃 표 처리 방식을 고를 수 있습니다.
- **여러 파일·폴더 감시:** 여러 파일을 한꺼번에 변환하거나, 지정한 볼트 폴더를 감시해 새 문서를 자동으로 변환합니다(선택).
- **HWPX 미리보기·편집:** HWPX 파일을 전체 쪽 미리보기로 열고 문단·제목·표 셀의 텍스트를 고칩니다.
- **HWPX 내보내기:** 현재 Markdown 노트를 공문서 프리셋, 용지, 방향, 단 수, 글꼴 계열, 결재란 설정으로 HWPX로 저장합니다.
- **문서 도구:** 두 문서 비교, 양식 필드 분석·채우기, 도장·서명 배치, 개인정보 마스킹, 표 추출, 구조 JSON·쪽별 본문·RAG 청크·SVG·레이아웃 HTML 출력.
- **암호가 걸린 HWPX/HWP**는 한 번만 묻는 암호 입력으로 엽니다(암호는 저장하지 않음).
- **다른 플러그인·에이전트용:** 버전이 있는 문서 provider API, 명령으로 직접 시작하는 로컬 MCP 서버(선택).
- **OCR(선택 추가 팩, Windows x64):** 그림·스캔 PDF의 글자 인식, PDF 수식 인식. [OCR 추가 팩](#ocr-추가-팩) 참고.

## 설치

커뮤니티 플러그인에서 **KorDoc Transform**을 설치합니다. 수동 설치는 릴리스의 `main.js`, `manifest.json`, `styles.css`를 `.obsidian/plugins/kordoc-transform/`에 복사한 뒤 플러그인을 켭니다.

## 사용법

명령(명령 팔레트):

- 외부 문서를 마크다운으로 변환(파일 선택)
- 현재 파일을 마크다운으로 변환
- HWPX 미리보기 / HWPX 편집 명령 실행
- 현재 Markdown을 HWPX로 내보내기
- 문서 도구 열기
- 로컬 MCP 서버 시작·연결 정보 / 중지

파일 탐색기에서 지원 파일을 오른쪽 클릭해도 됩니다. 설정에서 저장 폴더, 이미지 추출, frontmatter, 덮어쓰기 규칙, 결과 형식, 쪽 범위, HWPX 내보내기 옵션, 폴더 자동 변환, 변환 완료 웹훅, OCR을 정합니다.

## OCR 추가 팩

OCR에는 네이티브 라이브러리(ONNX Runtime, sharp, PDFium)와 약 200MB의 인식 모델이 필요해 커뮤니티 디렉터리로는 배포할 수 없습니다. 각 GitHub 릴리스에 별도 ZIP으로 첨부합니다.

1. 설치한 플러그인 버전과 같은 릴리스에서 `kordoc-transform-ocr-pack-<버전>-windows-x64.zip`을 내려받습니다.
2. `.obsidian/plugins/kordoc-transform/`에 압축을 풀어 `main.js` 옆에 `runtime/` 폴더가 생기게 합니다.
3. Obsidian을 다시 시작한 뒤 플러그인 설정에서 글자 OCR 또는 수식 OCR을 켭니다.

플러그인은 팩의 플러그인 버전·엔진 버전·플랫폼·파일 해시가 맞을 때만 팩을 씁니다. 맞지 않으면 OCR을 켜지 않고 이유를 알려 줍니다. 플러그인을 업데이트할 때마다 맞는 팩을 다시 설치하세요. 팩은 Windows x64용만 제공합니다.

## 한계

- 데스크톱 전용입니다.
- 변환 품질은 문서를 만든 방식에 따라 다릅니다. 복잡한 배치, OCR 추가 팩 없이 처리한 스캔 쪽, 손글씨는 직접 고쳐야 할 수 있습니다.
- HWPX 편집은 문단·제목·표 셀의 텍스트를 바꾸며 문서 구조를 다시 짜지는 않습니다. HWP 5.0 바이너리는 만들지 않습니다.
- OCR 추가 팩이 없으면 큰 문서를 한 번에 하나씩 메인 스레드에서 변환하므로, 큰 변환 중에는 Obsidian이 잠시 멈출 수 있습니다.

## 공개 사항

- **파일:** 사용자가 고른 문서(또는 설정한 감시 폴더에 들어온 문서)를 읽고, 변환된 노트·추출 그림·내보낸 HWPX·진단 정보를 설정한 볼트 폴더에 씁니다.
- **네트워크:** 기본으로는 쓰지 않습니다. 로컬 MCP 서버는 사용자가 시작했을 때만 loopback 주소에서만 듣습니다. 변환 완료 웹훅을 설정하면 파일 이름·결과 경로·성공 여부를 그 URL로 보냅니다. 엔진은 오프라인 모드로 동작하며 아무것도 내려받지 않습니다.
- **네이티브 코드:** 선택 사항인 OCR 추가 팩만, 사용자가 직접 설치한 `runtime/` 폴더의 네이티브 코드를 실행합니다.
- **번들 코드·데이터:** `main.js`에 kordoc 엔진, PDF.js와 그 CMap·표준 글꼴, 그 밖의 오픈소스 라이브러리가 들어 있습니다. 라이선스는 `main.js` 앞부분과 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 있고, 모델·네이티브 라이브러리 라이선스는 OCR 추가 팩 안에 있습니다.
